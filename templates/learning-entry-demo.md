# v0.1.3 入口演示与人工验收

这是合成对话样例，不是用户画像或真实学习记录。每个场景从新的会话开始；不得把本文的模式选择/作答写入真人 Vault。

## 未选择模式

用户：我想学习可口可乐的历史。

Agent 首轮：只给创建知识边界 / 使用已有数据库 / 不使用个人数据三项说明并等待。不讲历史、不读取库、不发知识测试。用户再说“整体历史”，仍只确认数据模式；不能将主题选择当成同意建档。

## 选择创建

用户：让 Skill 创建知识边界。

Agent：确认独立保存位置与允许资料范围，再就当前目标提必要问题。对于“瓶装网络为何扩大”，可先问：你目前理解装瓶商与可口可乐公司的分工吗？请试着说说；不确定也可以。若已理解则不重讲分工，若把双方当成同一公司则先澄清。不能用“有广告没货怎么办”这样的泛常识替代目标诊断。

创建空骨架只表示 unknown；用户实际回答后才有边界依据。未确认位置不初始化，未授权历史聊天不读取。

## 选择既有库

用户：使用我已有的数据库，只读我给的这个目录。

Agent：若未给目录先问精确位置；已经给定则只读取所选内容。不自动新建、不改原格式、不寻找其他库。只有笔记而没有行为证据时，不能宣布用户已掌握；补充最小当轮诊断，新结论不保存。库不可访问时先请求入口或相关导出，不静默切到创建模式。

## 选择无个人数据

用户：不要用我的个人数据，也不用保存，直接在这里学。

Agent：沿用当前问题，不再要求个人库位置，不读其他聊天。就本轮目标临时确认必要前提，再开始最小讲解；没有跨会话画像/Focus，不调用 Vault writer。如果用户拒绝诊断，以自足解释开头并保持知识边界未知，不声称做过边界测量。

## 中途切换

用户：改成不用个人数据。

Agent：停止引用旧模式的画像、个人简报和写入权限，说明之后仅依赖当前问题与新的回答；旧库保留不动，不自动删除。若随后用户说“下次接着上次”，说明无档案不能自动恢复，邀请重新选择数据模式，而非后台读库。

## 验收观察

确认是否先选后教；两种用库模式是否先确认精确范围；无数据模式是否仍提供有质量的教学；既有库是否字节不变；知识诊断是否真能改变下一步；未证实内容是否保持 unknown。对真实教学效果仍需用户作答与反馈，不以入口脚本通过代替。
